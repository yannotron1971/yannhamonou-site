The actual diff

Three one-liners and a template edit.

  1. Let the hamburger exist above 760px.

    global.css · one media query

    Right now the index is unreachable on desktop. This is the only change that makes the move visible at all.

    - @media (max-width: 760px) { .v4-hamburger { display: flex } }
+ .v4-hamburger { display: flex }   ← drop the gate entirely

    Keep .v4-nav__links and the CTA on desktop as they are. Adcker does exactly this: a working bar and an index behind it.

  2. Raise the cap on the drawer type.

    global.css · one value

    56px is a phone size. On a 1280 screen it reads as a list; at 104px it reads as the index.

    .v4-drawer__links a {
-  font-size: clamp(36px, 8vw, 56px);
+  font-size: clamp(40px, 9vw, 104px);
-  line-height: 1.1;
+  line-height: .95;   ← tightens the stack; mask = one line
}

    Five lines at 104px and .95 leading is ~495px — comfortable inside an 800px viewport with your 80px drawer padding.

  3. Swap the colour fade for the roll.

    global.css + Nav.astro · ~12 lines

    The drawer currently does color: mute → ink over 0.15s. The roll replaces that transition; the markup gains a duplicate label.

    {navLinks.map(link => (
  <li><a href={link.href} class="roll">
    <span class="a">{link.label}</span>
    <span class="b" aria-hidden="true">{link.label}</span>
  </a></li>
))}

    One .map(), in a file you already maintain. The duplicate takes aria-hidden so screen readers still hear each item once.

  4. Decide what happens to the six services.

    the only real decision

    This is where it stops being mechanical. Your drawer nests six services under Services as an 11px mono sub-list. Five top-level lines plus six children is eleven rows — at 104px that is ~1,090px and it will not fit a laptop viewport.

    A — five lines only; Services goes to /services, which already exists and already lists all six. The index stays one level deep, like the reference.

    B — five lines, with the six services kept as a mono rail beneath. Denser, but it keeps them one click away and uses the mono voice you already have.

    Toggle both in the demo above. I'd take A: the whole argument for move 01 is that the index is a single held breath, and a sub-list is the thing that breaks it.

What you are not changing

The top bar, the brand lockup, the Services dropdown, the ground ladder, the hero field, the sticky-hero-under-sheet structure, every token, and the entire type system. The drawer's backdrop-filter: blur(24px) over the field already gives you the one thing Adcker doesn't have — the index opens over the moving ground rather than replacing it.

The 0.25s opacity fade on .v4-drawer.is-open stays as-is. If you later want the lines to stagger in behind it, that is GSAP — already a dependency, and it is the only part of this that needs JavaScript.
