Adcker runs GSAP, Lenis, Barba.js and anime.js. But the thing that makes the index feel expensive isn't any of them: each menu line holds two copies of its label inside a one-line mask, and hover slides both up by exactly one line. That is a CSS transition.

The stack is separable. You can take the roll today with zero dependencies, and decide about smooth-scroll and page transitions separately — those are the parts that actually cost something.

The first is what the reference actually uses

What I measured on adcker.com

The rest state gives the whole mechanism away.

Reading one live index link, at rest, with no interaction:

a.group { overflow: hidden; height: 91.09px }   ← mask = exactly one line

  span   "About"   position: static     transform: none
  span   "About"   position: absolute   transform: translateY(95.65px)
                   top: 0               ← second copy parked one line below

  transition: 0.7s cubic-bezier(0.98, 0, 0.02, 1)
  font: 117px / 91.1px, letter-spacing -5.84px   ← ≈ -0.05em

Two identical labels, one mask, one transform. Hover moves both up 100% — the first leaves, the second arrives. That ease is close to an expo in-out: it holds still at both ends and crosses the middle almost instantly, which is what makes the swap read as a cut rather than a slide.

The whole thing

Twelve lines of CSS.

<a class="roll" href="/services">
  <span class="a">Services</span>
  <span class="b" aria-hidden="true">Services</span>   ← duplicate: hide from SR
</a>

.roll        { position:relative; overflow:hidden; display:block;
               line-height:.86; }              ← the mask is one line tall
.roll .a,
.roll .b     { display:block;
               transition:transform .7s cubic-bezier(.98,0,.02,1); }
.roll .b     { position:absolute; inset-inline:0; top:0;
               transform:translateY(100%); }
.roll:hover .a,
.roll:focus-visible .a { transform:translateY(-100%); }
.roll:hover .b,
.roll:focus-visible .b { transform:translateY(0); }

@media (prefers-reduced-motion:reduce) {
  .roll .a, .roll .b { transition-duration:.01ms; }   ← swap, don't slide
}

Three things worth keeping when you port it: :focus-visible alongside :hover so keyboard users get the same affordance, aria-hidden on the duplicate so screen readers don't announce every label twice, and the reduced-motion branch. The reference site ships none of those three.

Their stack vs. yours

Take one library, skip three.

LibraryDoes whatReplicate?
— none — The index roll itself, flanking-label reveal, bracket plate Yes. Pure CSS, shown above. Do this one.
GSAP Staggered entrance of the index lines on load Yes — and free. gsap ^3.15.0 is already a dependency on this branch, and you already run one orchestrated load sequence.
Lenis Smooth / inertial scrolling Skip. It hijacks native scroll, fights your sticky hero and the ground-ladder section changes, and is the most common accessibility complaint about sites like this.
Barba.js Cross-page transitions without a reload Skip. It turns a static Astro site into a client-routed one — you'd be trading your build's biggest advantage for a fade. If you want the effect, the native View Transitions API gets most of it for nothing.
anime.js Loaded alongside GSAP on the same page Skip. Two tweening engines is their bundle being a WordPress autoptimize concatenation, not a design decision.
